# GPS Квест — Контекст проекта
## 1. Общая концепция
GPS-квест-бродилка по городу (и другим локациям через сценарии). Сценарий из базы данных открывается кодовым словом. У точки из сценария открывается загадка: верный ответ → факт о месте → следующая точка. Есть режимы: 1. 🦊 Охота на лис — поиск маяка (точки) по силе сигнала и звуку, без карты. Бонус-рейд (10 минут, только радар, собрать ключ, посетив все точки).
**Технологии:** Leaflet (карта), Supabase (БД + RPC), WebAudio (звук охоты), один файл index.html.
**Репозиторий:** `KudinovIgor/gps-quest-game` на GitHub.

## 2. База данных (Supabase)
### Таблицы
-   **scenarios**: Сценарии квестов (`slug`, `title`, `code`).
-   **stages**: Этапы маршрута (`id`, `scenario_slug`, `title`, `rule_type`, `sort_order`, `settings` JSONB).
-   **points**: Точки маршрута (`id`, `scenario_slug`, `title`, `latitude`, `longitude`, `description`, `answer`, `hint`, `comment`, `radius_m`, `stage_id`, `stage_order`).
-   **editor_auth**: Пароли редактора (`pass_hash`).

### Типы этапов (rule_type)
-   `linear`: Обычные точки по порядку.
-   `bonus`: Бонус-рейд с таймером (значение берется из `settings.global_timer` этапа).
-   `foxhunter`: Охота на лис (зона охоты вычисляется по точкам этапа).
-   `story`: История (текстовая вставка).
-   `flashlight`: Фонарик / туман войны (не реализовано).
-   `sequence`: Строгая последовательность, ошибка = рестарт (не реализовано).
-   `free`: Свободный порядок взятия (не реализовано).

### RPC-функции
-   `load_scenario(p_code TEXT) → JSON`: Загружает сценарий по коду.
-   `save_stage(p_data JSONB) → BIGINT`: Сохраняет этап (INSERT/UPDATE).
-   `save_quest_point(p_data JSONB) → BIGINT`: Сохраняет точку (INSERT/UPDATE).
-   `editor_delete_quest(p_id BIGINT, p_pass TEXT) → BOOLEAN`: Удаляет точку.
-   `move_quest(p_id, p_lat, p_lng, p_pass) → BOOLEAN`: Перемещает точку.
-   `renumber_stage_points(p_stage_id BIGINT) → VOID`: Перенумерация точек этапа.
-   `trigger_renumber_points() → TRIGGER`: Триггерная обёртка над функцией перенумерации.

### Триггеры и безопасность
-   **points_renumber_trigger**: AFTER INSERT OR UPDATE OF `stage_id`, `stage_order` ON `points`. Вызывает `trigger_renumber_points()`.
-   **Защита от рекурсии**: Внутри триггерной функции стоит проверка `pg_trigger_depth() > 1`. Если глубина больше 1, функция сразу возвращает NEW (иначе UPDATE внутри перенумерации снова дёргает триггер → stack overflow).
-   **Внешние ключи**:
    -   `points_stage_id_fkey` → `stages(id)` **ON DELETE SET NULL** (безопасный, точки остаются при удалении этапа).
    -   `quests_scenario_fk` → `scenarios(slug)`.
    -   ~~`quests_stage_id_fkey`~~ → удалён (ранее был CASCADE и удалял точки при удалении этапа).
-   **RLS-политики**: Для таблиц `points` и `stages` настроены политики SELECT, INSERT, UPDATE, DELETE для ролей `anon` и `authenticated`.

## 3. Структура JS-кода
### Глобальное состояние (объект S)
Хранит текущий сценарий, массивы точек и этапов, множество открытых точек (`opened` Set), фазу игры (`phase`: 'main'|'bonus'|'won'), режим отображения (`mode`: 'map'|'radar'|'fox'), координаты игрока (`pos`), флаг прибытия к точке (`arrived`), объект целевой точки (`arrivalPoint`), счётчик ошибок (`wrong`), таймер бонуса (`bonusEndsAt`), ID активной лисы (`foxId`), фрагменты ключа, состояние редактирования, данные для звука охоты и прочее.

Новые поля для универсальной карточки:
cardLocked: Карточка зафиксирована в центре (не падает при выходе из радиуса).
cardMode: Текущий режим карточки ('walking' | 'story' | 'question' | 'fact').
arrivalPoint: Точка, к которой привязана зафиксированная карточка.

### Конфигурация (CONFIG)
Содержит `supabaseUrl`, `supabaseAnonKey`, радиус активации точки (40м), время бонуса (600с), дальность охоты (600м) и центр города.

### Ключевые функции
loadByCode(code): Загрузка сценария по коду через RPC load_scenario.
applyScenario(meta, quests, stages): Применение сценария, инициализация состояния, сброс прогресса.
currentStage(): Возвращает первый незавершённый этап любого типа (использует S.stages и p.stage_id).
target(): Возвращает целевую точку текущего этапа (undefined для fox/bonus).
presentStage(): Предъявление этапа: bonus→ovBonus, foxhunter→setMode('fox'), остальные→updateGame.
checkArrival(): Проверка входа в радиус → фиксация карточки (cardLocked=true, cardMode='story'|'question').
collect(p): Открытие точки, сохранение прогресса, сброс карточки, переход к следующему этапу.
getPointType(p): Определяет тип точки (story/fox/bonus/normal) по settings.type, типу этапа или наличию ответа.
getPointImage(p): Возвращает URL картинки из settings.image или null.
updateGame(): Обновление HUD, карточки, маркеров, радар-списка. Вызывает checkArrival().
renderCard(): Рендер карточки (два состояния: «идём» внизу / «у точки» в центре).
submitAnswer(): Обработка ответа (обычная точка / лиса / бонус). Переключает cardMode на 'fact' или вызывает collect().
renderDebug(fit): Отладочные маркеры, нить маршрута, окружности групповых этапов, лучи к точкам, круги радиуса для каждой точки, межэтапные связки к центру кластера.
routeKm(): Оценка длины маршрута для отладки (работает с новой моделью этапов).
renderStagesEditor(): Редактор этапов (список с кнопками управления).
openPointEditor() / edSavePoint / delById(): CRUD операций над точками.
openStageEditor() / stSave / deleteStage(): CRUD операций над этапами.
moveStage(id, dir) / movePointInStage(p, st, dir): Перемещение элементов с анимацией.
ensurePass(): Запрос пароля редактора (кэш в sessionStorage на сеанс).
startBonus() / tick() / win() / fail(): Логика бонус-рейда.
foxStageActive() / foxStageQuests() / foxStageRange(): Логика лисьего этапа (используют st.rule_type).
foxTick() / renderFox() / renderFoxSel(): Логика охоты на лис (WebAudio).
drawRadar() / renderRadarList(): Отрисовка радара (canvas) и списка целей.
setPos(lat, lng, acc): Установка позиции игрока.
setMode(m): Переключение режимов (map/radar/fox).
toggleDebug(): Включение/выключение отладки (показывает segModes, btnStages, btnAdd, btnDel, btnTest).
normAns(s): Нормализация ответа (ё→е, регистр, пробелы).
distM(), bearing(): Геодезические функции для расчёта расстояний и азимутов.
toast(msg, ms): Всплывающее уведомление.

### Демо-данные
Массив `DEMO[]` содержит демо-точки (id: d1-d10, b1-b3, f1-f2). Активируется кодом `demo` без обращения к базе данных.

## 4. UI-структура
### Оверлеи (overlay)
-   `ovStart`: Стартовый экран с вводом кода.
-   `ovCode`: Ввод кода (вызывается кнопкой 🔑 в header).
-   `ovEdit`: Список этапов (вызывается кнопкой 📋 Этапы).
-   `ovStageEdit`: Редактирование или создание этапа.
-   `ovPointEdit`: Редактирование или создание точки.
-   `ovStory`: Страница истории.
-   `ovFact`: Факт после правильного ответа.
-   `ovBonus`: Предложение начать бонус-рейд.
-   `ovWin`: Победа (ключ собран).
-   `ovFail`: Поражение (время вышло).
-   `ovFoxDone`: Сообщение "Все лисы пойманы".
-   `ovPass`: Ввод пароля редактора.

### Основные элементы интерфейса
#card: Универсальная карточка квеста. Находится внизу экрана при движении, по центру при входе в радиус (класс .centered). Содержит: #btnCardClose (крестик), #cardTitle, #cardImage, #cardDist, #cardDesc, #answerRow, #btnCardContinue, #btnBonusGo, #hintLine.
#radarView: Вид радара (canvas + список blips).
#foxView: Интерфейс охоты на лис (сигнал, бар, тренд, кнопки выбора лисы).
#geoStatus: Статус геолокации.
#modeStatus: Статус текущего режима или этапа.
#progress: Прогресс прохождения (🚩 N/M).
#segModes: Сегмент с кнопками 🗺 Карта / 📡 Радар / 🦊 Охота (показывается в отладке).

### Кнопки в header
`btnMap`(скрыта без debug), `btnRadar`(скрыта без debug), `btnFox`(скрыта без debug), `btnTest`(скрыта без debug), `btnDebug`, `btnStages` (скрыта без debug), `btnAdd` (скрыта без debug), `btnDel` (скрыта без debug), `btnCode`, `btnReset`, `btnFollow` (◎, плавающая кнопка слежения на экране, привязка карты к игроку).

## 5. Ключевые UX-решения

Универсальная карточка — два состояния
Идём к точке (!S.cardLocked && !S.atPoint): Карточка внизу, показывает только название и расстояние («≈ N м»). Загадка и поле ответа скрыты.
Мы у точки (S.cardLocked): Карточка по центру экрана (класс .centered), показывает загадку/историю/факт, поле ответа активно или кнопка «➡ Далее». Карточка не падает при выходе из радиуса до явного действия пользователя.

Режимы карточки (cardMode)
walking: Карточка внизу, показывает название и расстояние.
story: Карточка в центре, текст истории + кнопка «➡ Далее».
question: Карточка в центре, загадка + поле ответа + кнопка «Ответить».
fact: Карточка в центре, факт после правильного ответа + кнопка «➡ Далее».

### Анимация перемещения

Используются `@keyframes slideUp/slideDown` для лёгкого «прыжка» строки при перемещении этапа или точки. Элементы ищутся по атрибутам `data-stage-id` / `data-point-id` после перерисовки DOM.

### Пароль редактора
Кэшируется в `sessionStorage` на весь сеанс. Запрашивается один раз при первом действии, требующем записи в БД. При неверном пароле кэш очищается.

### Бонус-рейд
Таймер берётся из `settings.global_timer` этапа (или дефолтные 600с). Реализована компенсация времени при блокировке экрана через событие `visibilitychange`. Wake Lock предотвращает гашение экрана во время игры.

### Охота на лис
Непрерывный звук генерируется через WebAudio (oscillator + gain). Сигнал растёт при приближении и падает при удалении. Тренд (↑/↓/→) отображается в UI. При открытии загадки или факта звук переключается на приглушённый тик. После поимки всех лис показывается ovFoxDone, по нажатию «Продолжить» игра переключается на карту и показывает следующий этап.

### Отладка
Режим 🐞 требует пароля. Показывает:
Маркеры точек с номерами (Э1.1, Э2.3 и т.д.).
Нить маршрута внутри линейных этапов (сплошная линия).
Описывающую окружность + центр этапа (Эn) + пунктирные лучи к точкам для групповых этапов (foxhunter, bonus, sequence, free).
Круги радиуса активации для каждой точки (пунктир, полупрозрачные).
Межэтапные связки (серый пунктир) от хвоста предыдущего этапа к голове текущего (центр кластера для групповых, первая точка для линейных).
Зелёный трейл пройденных точек (история прохождения пользователя).
Кнопки ➕ (добавить точку) и ➖ (удалить по клику).
Сегмент segModes для переключения Карта/Радар/Охота.

6. История изменений и известные проблемы
Решённые проблемы (последние сессии)
Универсальная карточка: Введена новая логика с cardLocked, cardMode, arrivalPoint. Карточка не падает при выходе из радиуса.
Лисы не включались: Функции foxStageActive(), foxStageQuests(), foxStageRange() проверяли st.kind вместо st.rule_type. Исправлено.
move_quest 404: Функция была удалена из БД. Восстановлена через SQL.
Кнопки режимов пропали в отладке: В toggleDebug() не показывался segModes. Добавлена строка $('segModes').hidden = !S.debug;.
Переход после лисьего этапа: Обработчик btnFoxDoneClose не сбрасывал состояние охоты. Добавлен сброс и setMode('map').
Бонусный рейд не запускался: Не были привязаны обработчики btnBonusStart, btnBonusLater, btnBonusGo. Добавлены. Убран инлайн-стиль display:none!important с btnBonusGo.
Отладочная карта: Восстановлена визуальная логика (окружности групповых этапов, лучи, круги радиуса, связки к центру кластера).
routeKm() падала: Функция вызывала удалённую computeStages(). Переписана под новую модель этапов.
Кнопки карточки выглядели чужеродно: Добавлены стили для .btn, .btn.sec, #btnCardClose.
Удалён мёртвый код: openEditor, editorSave, editorDelete, getStages(), computeStages(), cachedStages.
rpcDeleteQuest: Исправлен вызов editor_delete_quest вместо delete_quest_point.
Архитектурное решение по этапам
Этап представляет собой группу точек плюс параметры режима (таймер, зона охоты, последовательность, туман войны). Тип этапа (rule_type) задаёт правила игры для всей группы. Внутри linear этапов можно смешивать обычные точки и точки-истории (через поле kind на точке — обсуждается, не реализовано).
7. Планы и обсуждаемые улучшения
Поле kind на точке (story/normal/fox/bonus): Чтобы историю можно было вставить в любой этап (начало, середину, конец), а не только в отдельный этап типа story. Это следующий большой архитектурный шаг.
Story-точка-подсказка перед лисьим этапом: После «Продолжить» автоматически включается режим охоты.
Story-точка-поздравление после лисьего этапа: Отдельный мини-этап или точка с stage_id=null.
Типы этапов sequence и free: Строгая последовательность (ошибка = рестарт) и свободный порядок взятия.
Массовая вставка точек: SQL-скрипт для быстрого восстановления данных после потери.
Чистка legacy-оверлеев: ovStory и ovFact больше не используются (логика в карточке), можно удалить.
