# GPS Квест — Контекст проекта
## 1. Общая концепция
GPS-квест-бродилка по городу (и другим локациям через сценарии). Сценарий из базы данных открывается кодовым словом. У точки из сценария открывается загадка: верный ответ → факт о месте → следующая точка. Есть режимы: 1. 🦊 Охота на лис — поиск маяка (точки) по силе сигнала и звуку, без карты. Бонус-рейд (10 минут, только радар, собрать ключ, посетив все точки).
**Технологии:** Leaflet (карта), Supabase (БД + RPC), WebAudio (звук охоты), один файл index.html.
**Репозиторий:** `KudinovIgor/gps-quest-game` на GitHub.

## 2. База данных (Supabase)
### Таблицы
-   **scenarios**: Сценарии квестов (`slug`, `title`, `code`).
-   **stages**: Этапы маршрута (`id`, `scenario_slug`, `title`, `rule_type`, `sort_order`, `settings` JSONB).
-   **points**: Точки маршрута (`id`, `scenario_slug`, `title`, `latitude`, `longitude`, `description`, `answer`, `hint`, `comment`, `radius_m`, `stage_id`, `stage_order`).
-   **editor_auth**: Пароли редактора (`pass_hash`).

### Типы этапов (rule_type)
-   `linear`: Обычные точки по порядку.
-   `bonus`: Бонус-рейд с таймером (значение берется из `settings.global_timer` этапа).
-   `foxhunter`: Охота на лис (зона охоты задается в `CONFIG.foxRange = 600м`).
-   `story`: История (текстовая вставка перед загадкой).
-   `flashlight`: Фонарик / туман войны (не реализовано).
-   `sequence`: Строгая последовательность, ошибка = рестарт (не реализовано).

### RPC-функции
-   `load_scenario(p_code TEXT) → JSON`: Загружает сценарий по коду.
-   `save_stage(p_data JSONB) → BIGINT`: Сохраняет этап (INSERT/UPDATE).
-   `save_quest_point(p_data JSONB) → BIGINT`: Сохраняет точку (INSERT/UPDATE).
-   `editor_delete_quest(p_id BIGINT, p_pass TEXT) → BOOLEAN`: Удаляет точку.
-   `move_quest(p_id, p_lat, p_lng, p_pass) → BOOLEAN`: Перемещает точку.
-   `renumber_stage_points(p_stage_id BIGINT) → VOID`: Перенумерация точек этапа.
-   `trigger_renumber_points() → TRIGGER`: Триггерная обёртка над функцией перенумерации.

### Триггеры и безопасность
-   **points_renumber_trigger**: AFTER INSERT OR UPDATE OF `stage_id`, `stage_order` ON `points`. Вызывает `trigger_renumber_points()`.
-   **Защита от рекурсии**: Внутри триггерной функции стоит проверка `pg_trigger_depth() > 1`. Если глубина больше 1, функция сразу возвращает NEW (иначе UPDATE внутри перенумерации снова дёргает триггер → stack overflow).
-   **Внешние ключи**:
    -   `points_stage_id_fkey` → `stages(id)` **ON DELETE SET NULL** (безопасный, точки остаются при удалении этапа).
    -   `quests_scenario_fk` → `scenarios(slug)`.
    -   ~~`quests_stage_id_fkey`~~ → удалён (ранее был CASCADE и удалял точки при удалении этапа).
-   **RLS-политики**: Для таблиц `points` и `stages` настроены политики SELECT, INSERT, UPDATE, DELETE для ролей `anon` и `authenticated`.

## 3. Структура JS-кода
### Глобальное состояние (объект S)
Хранит текущий сценарий, массивы точек и этапов, множество открытых точек (`opened` Set), фазу игры (`phase`: 'main'|'bonus'|'won'), режим отображения (`mode`: 'map'|'radar'|'fox'), координаты игрока (`pos`), флаг прибытия к точке (`arrived`), объект целевой точки (`arrivalPoint`), счётчик ошибок (`wrong`), таймер бонуса (`bonusEndsAt`), ID активной лисы (`foxId`), фрагменты ключа, состояние редактирования, данные для звука охоты и прочее.

### Конфигурация (CONFIG)
Содержит `supabaseUrl`, `supabaseAnonKey`, радиус активации точки (40м), время бонуса (600с), дальность охоты (600м) и центр города.

### Ключевые функции
-   `loadByCode(code)`: Загрузка сценария по коду через RPC `load_scenario`.
-   `applyScenario(meta, quests, stages)`: Применение сценария, инициализация состояния, сброс прогресса.
-   `currentStage()`: Возвращает первый незавершённый этап любого типа.
-   `target()`: Возвращает целевую точку текущего этапа (undefined для fox/bonus).
-   `objective()`: Определяет цель с учётом режима (target / nearestUnopened / fox).
-   `presentStage()`: Предъявление этапа: story→ovStory, bonus→ovBonus, fox→setMode('fox').
-   `updateGame()`: Обновление HUD, карточки, маркеров, радар-списка.
-   `renderCard()`: Рендер карточки (два состояния: «идём» / «у точки»).
-   `checkArrival()`: Проверка входа в радиус → открытие загадки или истории.
-   `submitAnswer()`: Обработка ответа (обычная точка / лиса / бонус).
-   `collect(p)`: Открытие точки, сохранение прогресса, переход к следующему этапу.
-   `renderDebug()`: Отладочные маркеры + нить маршрута через все этапы.
-   `renderStagesEditor()`: Редактор этапов (список с кнопками управления).
-   `openPointEditor()` / `savePoint()` / `delPoint()`: CRUD операций над точками.
-   `openStageEditor()` / `saveStage()` / `deleteStage()`: CRUD операций над этапами.
-   `moveStage(id, dir)` / `movePoint(p, st, dir)`: Перемещение элементов с анимацией.
-   `ensurePass()`: Запрос пароля редактора (кэш в sessionStorage на сеанс).
-   `startBonus()` / `tick()` / `win()` / `fail()`: Логика бонус-рейда.
-   `foxTick()` / `renderFox()` / `fillFoxSelect()`: Логика охоты на лис (WebAudio).
-   `drawRadar()` / `renderRadarList()`: Отрисовка радара (canvas) и списка целей.
-   `setPos(lat, lng, acc)`: Установка позиции игрока.
-   `setMode(m)`: Переключение режимов (map/radar/fox).
-   `normAns(s)`: Нормализация ответа (ё→е, регистр, пробелы).
-   `distM()`, `bearing()`: Геодезические функции для расчёта расстояний и азимутов.
-   `toast(msg, ms, kind)`: Всплывающее уведомление.

### Демо-данные
Массив `DEMO[]` содержит демо-точки (id: d1-d10, b1-b3, f1-f2). Активируется кодом `demo` без обращения к базе данных.

-   `ovCode`: Ввод кода (вызывается кнопкой 🔑 в header).

`btnMap`(скрыта без debug), `btnRadar`(скрыта без debug), `btnFox`(скрыта без debug), `btnTest`(скрыта без debug), `btnDebug`, `btnStages` (скрыта без debug), `btnAdd` (скрыта без debug), `btnDel` (скрыта без debug), `btnCode`, `btnReset`, `btnFollow` (◎, плавающая кнопка слежения на экране, привязка карты к игроку).

## 5. Ключевые UX-решения

### Карточка квеста — два состояния

1.  **Идём к точке** (`!S.atPoint`): Карточка внизу, показывает только название и расстояние («≈ N м»). Загадка и поле ответа скрыты.
2.  **Мы у точки** (`S.atPoint`): Карточка по центру экрана (класс `.centered`), показывается загадка, поле ответа активно и получает фокус, расстояние скрыто.

### Анимация перемещения

Используются `@keyframes slideUp/slideDown` для лёгкого «прыжка» строки при перемещении этапа или точки. Элементы ищутся по атрибутам `data-stage-id` / `data-point-id` после перерисовки DOM.

### Пароль редактора
Кэшируется в `sessionStorage` на весь сеанс. Запрашивается один раз при первом действии, требующем записи в БД. При неверном пароле кэш очищается.

### Бонус-рейд
Таймер берётся из `settings.global_timer` этапа (или дефолтные 600с). Реализована компенсация времени при блокировке экрана через событие `visibilitychange`. Wake Lock предотвращает гашение экрана во время игры.

### Охота на лис
Непрерывный звук генерируется через WebAudio (oscillator + gain). Сигнал растёт при приближении и падает при удалении. Тренд (↑/↓/→) отображается в UI. При открытии загадки или факта звук переключается на приглушённый тик.

### Отладка
Режим 🐞 требует пароля. Показывает маркеры точек с номерами, нить маршрута через все этапы, межэтапные связки (пунктир), окружности групп и центры этапов. Доступны кнопки ➕ (добавить точку) и ➖ (удалить по клику).

## 6. История изменений и известные проблемы
### Решённые проблемы
-   **Дубликаты функций**: Удалены старые версии `openPointEditor`, `renderStagesEditor`, оставлены новые.
-   **CASCADE FK**: Удалён опасный ключ `quests_stage_id_fkey`, оставлен безопасный `points_stage_id_fkey` с SET NULL.
-   **Рекурсия триггера**: Добавлена проверка `pg_trigger_depth() > 1` в `trigger_renumber_points`.
-   **404 на save_quest_point**: Создана новая функция с параметром `p_data JSONB`.
-   **ERR_NAME_NOT_RESOLVED**: Исправлен URL проекта в CONFIG.
-   **Падение renderCard()**: Добавлена проверка `if(!t)` до обращения к `t.title`.
-   **Логика "идём vs у точки"**: Восстановлена через `S.atPoint` и два блока рендера.
-   **Центрирование карточки**: Добавлен класс `.centered` с анимацией `cardExpand`.
-   **CSS окна этапов**: Селекторы привязаны к ID (`#btnAddStage`, `#edCancel`) вместо общих классов.
-   **Отсутствие makeIconBtn**: Функция добавлена после `renderStagesEditor`.

### Архитектурное решение по этапам

Этап представляет собой группу точек плюс параметры режима (таймер, зона охоты, последовательность, туман войны). Тип этапа задаёт правила игры для всей группы. Внутри `linear`/`story` этапов можно смешивать обычные точки и точки-истории (поле `kind` на точке обсуждается, но пока не реализовано массово).
